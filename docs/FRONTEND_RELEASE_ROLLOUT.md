# 프론트 수정본 운영 반영

## 2026-11-06 새벽·오전 반복 고정 배정 수정본

사용자가 [60분 반복 배정 검증 수정](RECURRING_ASSIGNMENTS.md)의 GitHub·운영 배포를 승인했다. B11~B22를 프론트에서 거절하던 입력 검증과 충돌 표시, 예약 변경·교환 결과 검증을 canonical 목록과 맞춘다. Frontend 435건·타입/lint/production 빌드와 격리 PostgreSQL 관련 61건·합성 브라우저 검증을 완료했다. 새 migration과 Backend 업무 코드 변경은 없다.

동일 HEAD PR CI → 별도 승인 후 정식 전환/main 병합 → 해당 main push CI → 기존 발행 workflow의 `v1.0.0-rc.7` 공개 이미지·digest 검증 순서로 진행한다. 운영에는 **Frontend만** 고정 digest로 교체한다. 실행 중인 rc.6 Backend·기존 Caddy/PG, DB·볼륨·worker를 보존하고 Backend 재시작이나 V13 재적용은 하지 않는다. 기존 프론트 참조/설정은 보존하며 실패 시 프론트만 복귀한다.

배포 전 현재 health·백업·컨테이너/설정 출처를 확인한다. 실제 혼합 이미지 구성에 맞는 백업 출처 전환에서 새 hourly/weekly 암호화 백업·exact-version 검증과 PC 독립 복원, 최신 설정 암호문 복원을 확인한다. 기존 성공 상태의 identity만 수정해 통과시키지 않으며 기존 백업/설정/비밀값·사용자가 연기한 PC 밖 암호문 사본 선택을 유지한다. 실제 완료 결과는 실행 증빙과 구분하고, 운영 실제 예약 생성·변경 테스트 대신 배포 자산/읽기 검증과 합성 환경의 쓰기 검증을 사용한다. **이 절은 실행 계획이며 아직 운영 반영 완료 기록이 아니다.** 아래 10월 기록은 당시 단계다.

## 2026-10-30 준비

사용자가 확인한 모바일 상단 수정본의 운영 반영을 승인했다. 제목과 `STUDIO NOTE` 한 줄, 아래 설명 오른쪽의 배경 없는 굵은 계정 링크를 적용한다. 로고 탭의 홈 이동도 보존한다. PC 배치·인증/예약 업무·DB migration은 변경하지 않는다. 화면 검증 범위는 [다이어리 UI 기록](DIARY_UI_REDESIGN.md)을 따른다.

기존 실제 데이터 이전/공개 기록과 이미 운영에서 검증한 Caddy 캐시 설정을 같은 소스 상태로 정리한다. 민감 설정·실제 회원/예약 자료·덤프·설정 암호문·개인키는 게시하지 않는다. 아래 단계는 실행 전 계획이며 성공 기록을 대신하지 않는다.

## 발행·적용 순서

1. 검토한 소스와 기록을 기능 브랜치에 커밋·Push하고 main 대상 PR의 동일 HEAD CI를 확인한다. 정식 전환·main 병합은 저장소의 별도 승인 규칙을 따른다.
2. 기존 main 전용 이미지 발행 workflow를 재사용한다. 병합 main SHA의 CI 성공·합성 컨테이너 검증을 거친 고정 digest만 사용한다. 기존 공개 package 사용 승인 범위를 유지하며 버전/SHA 태그를 덮어쓰지 않는다.
3. 운영의 기존 이미지·설정·컨테이너·볼륨·worker 상태와 최신 백업을 확인하고 변경 전 설정을 보호 사본으로 보존한다. 새 릴리스에서 발행되는 세 이미지 중 운영 Frontend만 교체하고 Backend/Caddy/PG는 기존 고정 참조를 유지한다.
4. Compose의 Frontend만 의존 서비스 재생성 없이 갱신한다. 공개 HTTPS·health·캐시/보안 헤더·비로그인 보호와 모바일 제목/계정·PC 배치를 확인한다. 실패 시 보존한 Frontend 참조/설정으로 복귀하며 운영 DB를 과거 dump로 덮지 않는다.
5. 백업의 이미지/출처 정보는 실제 혼합 배포 구성을 기록한다. 공통 `source_sha`는 구성 기준 커밋이며 모든 실행 이미지가 같은 커밋으로 재빌드됐다는 의미로 사용하지 않는다. 기존 성공 상태의 identity만 수정하거나 삭제해 통과시키지 않는다. 이전 상태/객체를 보존한 명시적 전환에서 실제 새 hourly/weekly 암호문과 검증된 새 상태를 만든 뒤 설치한다.
6. 새 백업의 exact version·SHA·감시를 확인하고 새 출처를 정확히 지정한 PC 독립 복원을 검증한다. 변경된 설정의 암호화 복구본도 갱신·대조한다. 새 암호문의 PC 밖 추가 사본은 기존 사용자 선택대로 연기한다.

실제 회원 대상 시험 예약/공지·Push 발송, 계정 재생성, DB 초기화/마이그레이션 재실행, 전체 VM 재부팅은 이번 UI 배포에 포함하지 않는다. 운영 데이터는 계속 변할 수 있으므로 정상 사용자 쓰기를 전체 행 지문 불변으로 판단하지 않는다.
