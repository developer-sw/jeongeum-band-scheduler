## 1. 확정 정책

정책 기준은 [PROJECT_CONTEXT](PROJECT_CONTEXT.md#10-탈퇴팀-해체), [RESERVATION_RULES](RESERVATION_RULES.md#11-회원팀-종료), [API](API.md#3-회원팀곡)다.

- 전체 관리자가 회원 탈퇴와 팀 해체를 처리한다. 본인 서비스 탈퇴 기능이나 팀장의 해체 권한을 새로 추가하지 않는다.
- 회원 탈퇴는 미래·진행 중 개인 예약을 취소한다. 탈퇴자가 생성했더라도 존속하는 팀 예약과 반복 배정은 유지한다.
- 팀 해체는 미래·진행 중 팀 예약을 취소하고 반복 배정을 종료한다. 변경·교환으로 이동한 해당 팀의 남은 예약도 포함한다.
- 종료된 예약·점유 해제 이력·예약자·변경/교환 계보·관리 이력을 삭제하거나 다른 사람으로 바꾸지 않는다.
- 시작 전 취소는 일반 60분 한도를 복원한다. 시작 후 취소는 사용량을 남긴다. 원래 고정 배정의 면제 조건을 바꾸지 않는다.
- 탈퇴 회원의 로그인·예약·승인 권한을 해제하고 향후 알림 대상에서 제외한다. 다른 활성 회원의 계정·기기를 종료하지 않는다.
- 탈퇴 팀장의 후임은 전체 관리자가 지정한다. 자동 승계나 탈퇴 금지를 추가하지 않는다.
- 관련 대기 교환·시작 알림·미전송 Push를 현재 권한과 예약 상태에 맞춰 정리한다. 승인 후보 한 명의 탈퇴만으로 다른 적법한 승인자가 처리할 수 있는 교환까지 일괄 무효화하지 않는다.

## 2. 구현을 위한 기술 계약

아래는 확정 정책을 실행하기 위한 기술 선택이다.

- 사용자·팀을 물리 삭제하지 않고 `WITHDRAWN`·`DISBANDED`와 종료 시각, 증가한 version으로 보존한다. 개인정보 보관/익명화 정책은 별도 운영 검토 대상이다.
- 탈퇴자의 활성 소속을 종료하여 팀장 공석을 허용한다. 팀 해체는 해당 팀의 활성 소속을 종료한다. 명단 연결과 곡·과거 소속 이력은 유지한다.
- 기존 마지막 활성 전체 관리자 강등 방지와 같은 보호 원칙으로 마지막 활성 전체 관리자의 탈퇴를 `LAST_GLOBAL_ADMIN`으로 거절한다.
- 탈퇴 시 모든 로그인 세션과 모든 기기 Push 연결을 종료한다. 일반 로그아웃의 해당 기기만 종료하는 정책과 구분한다.
- 로그인 비밀번호 검증 후 세션을 저장하는 마지막 단계에서도 동일 directory guard와 현재 회원 상태를 검사하여 탈퇴와 경합한 로그인이 인증 세션을 다시 만들지 않도록 한다. 기존 CSRF·90일 로그인 유지를 보존한다.
- 처리 사유는 선택이며 최대 500자다. 명시적 확인 화면 뒤 서버 요청을 전송한다. 클라이언트가 취소 대상·한도·권한을 결정하지 않는다.
- 기존 알림함은 보존한다. 취소/교환 무효화 알림은 관련 활성 당사자에게 기존 사건 유형으로 생성하고 탈퇴자는 제외한다. 해체 전 관련 당사자를 확보하고 현재 활성 상태를 다시 확인한다.
- 이미 외부 제공자에 전달된 요청이나 OS에 표시된 알림은 철회할 수 없다. 대기/처리 중 작업을 종료하고 완료 처리에서 상태를 재검사하여 작업이 되살아나는 것을 막는다.

## 3. API·재시도

기본 경로 `/api/v1`, 세션·CSRF·`Cache-Control: no-store`와 기존 `ApiResponse`를 유지한다.

| API | 권한·결과 |
|---|---|
| `POST /users/{id}/withdraw` | 현재 활성 전체 관리자, 회원 탈퇴와 관련 정리를 하나의 트랜잭션으로 수행 |
| `POST /teams/{id}/disband` | 현재 활성 전체 관리자, 팀 해체와 관련 정리를 하나의 트랜잭션으로 수행 |

두 API는 `Idempotency-Key`와 `{ expectedVersion, reason? }`을 받는다. 응답 `data`는 `operationId`, `targetId`, `status`, `version`, `canceledReservations`, `invalidatedExchanges`, `endedAssignments`, `deactivatedSubscriptions`, `revokedSessions`를 제공한다. ID는 문자열이며 건수와 version은 숫자다. 건수는 해당 처리에서 변경된 항목이며 전체 이력 건수가 아니다.

동일 실행자의 같은 키·경로·대상·version·사유 요청은 저장한 결과를 반환한다. 같은 키를 다른 요청에 쓰면 `IDEMPOTENCY_KEY_REUSED`, 새 요청의 오래된 version은 `VERSION_CONFLICT`다. 성공 응답을 잃으면 원래 요청과 키로 직접 재확인하고, 서버 최신 상태 조회를 요청 재실행 성공으로 간주하지 않는다. 재확인에도 현재 활성 관리자 권한이 필요하므로 탈퇴한 관리자 자신의 세션으로 접근을 되살리지 않는다.

오프라인 작업을 대기열에 넣거나 자동 실행하지 않는다. 권한·현재 상태·version·잠금 timeout·서버 결과 불명확 상태를 구분해 안내한다.

## 4. 저장·잠금·원자성

V1~V10 SQL을 수정하지 않고 V11에서 팀 종료 시각 `teams.disbanded_at`과 `lifecycle_operations`를 추가한다. 처리 기록은 대상·실행자·시각·사유·요청 digest/fingerprint·원래 응답 요약을 보존한다. 실제 키·쿠키·Push endpoint·비밀키를 로그나 공개 문서에 남기지 않는다. 기존 회원 종료 컬럼과 예약·quota·회차·알림 테이블을 함께 사용한다.

잠금은 기존 `directory_mutation_guard` → 정렬한 사용자/팀 → 악기 → 팀 해체의 `recurring_schedule_guard` UPDATE → 정렬한 날짜 → 예약/관련 업무 행 순서를 따른다. 대상 목록은 guard 안에서 확보하고 잠금 후 현재 상태와 version을 다시 검사한다. 10초 timeout과 전체 rollback을 적용한다.

예약 취소·점유 해제·한도 복원·회차 예외·교환 종료·시작 계획/Push 정리·회원/팀 상태·감사/재시도 결과는 같은 트랜잭션이다. 후반 저장이 실패하면 모두 보존하며 성공은 commit 이후다. 외부 발송은 이 트랜잭션 안에서 실행하지 않는다.

## 5. 관리자 화면

- 회원: `/admin/members`의 해당 회원에서 탈퇴 확인 화면을 연다.
- 팀: `/teams/{id}`의 전체 관리자 관리 영역에서 팀 해체 확인 화면을 연다.
- 대상 이름과 현재 상태를 보여주고 취소되는 예약 범위·보존되는 이력·되돌리기 없는 처리를 명시한다. 팀 탈퇴와 팀 해체를 혼동하는 문구를 사용하지 않는다.
- 회원 탈퇴는 존속 팀 예약 유지, 전체 기기/세션 종료와 팀장 후임 수동 지정을 설명한다. 팀 해체는 해당 팀 예약·반복 배정 종료를 설명한다.
- 처리 후 관련 목록·예약·일정·교환·반복 배정·알림 Query를 갱신한다. 본인 관리자 탈퇴가 성공하면 로그인 상태와 해당 브라우저의 계정 binding을 정리한다.
- 기존 다이어리 UI·정음 로고·기타 마스코트·`JEONGEUM · SENTIMENTAL MUSIC`을 유지한다.

## 6. 검증 계획과 실제 제한

PostgreSQL Testcontainers의 합성 계정/데이터에서 다음을 검증한다.

- 미래/진행 중/과거 개인 예약, 존속 팀 예약과 최초 예약자 보존, 시작 전/후 quota, 점유 해제.
- 팀장 공석·현재 권한·모든 세션/기기 해제·탈퇴와 로그인/새 예약/교환 경합.
- 팀 해체의 일반/고정/변경/교환 후속 예약, 패턴/회차 보존·재개방/재시작 후 재생성 금지.
- 관련 대기 교환만 현재 권한에 따라 종료, 다른 승인 후보·다른 팀/회원의 상태 보존.
- 알림 수신자 제외/기존 알림함 보존·시작 계획/Push 작업 종료·worker 중단/재시도 정합성.
- 실제 잠금 timeout과 후반 INSERT 실패의 전체 rollback, migration 업그레이드/기존 데이터 보존.
- 관리자 PC/모바일 확인·오프라인 쓰기 차단·실패 안내·같은 요청 재확인과 기존 UI 회귀.

개발 DB의 실제 회원 탈퇴·팀 해체·검증 예약 생성은 수행하지 않는다. 기존 V10 환경을 유지하며 V11 적용은 격리 DB에서 먼저 검증한다. 실기기 Push·HTTPS 운영 배포는 이 기능 개발 완료와 구분한다.
